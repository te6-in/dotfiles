# Asking the user

Whenever you need — or even suspect you might want — an answer or a choice from the user, immediately reach for the **AskUserQuestion** tool. Don't write the question as chat text and wait. Structured options are faster to answer and clearer to track. Lean aggressively toward asking: cost of a quick question is low, cost of guessing wrong and redoing the work is high. When in doubt, ask.

Applies to:
- Clarifying ambiguous requirements
- Picking between design / approach alternatives
- Confirming before an irreversible action (destructive git, writes to shared systems)
- Any uncertainty about user intent — including "small" decisions you'd be tempted to resolve silently
- Any point where you'd otherwise pause for a reply or quietly make an assumption

Doesn't apply to:
- Rhetorical phrasing in your own narration ("Let me check X...")
- Status updates
- Questions you can answer yourself by reading the code or docs
