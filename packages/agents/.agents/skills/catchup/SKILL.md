Figure out what work has been done on the current branch, from the diff between its fork point and its latest commit. Read and summarize — don't change code.

If you are the main agent, delegate the investigation to a read-only exploration subagent using this skill. Pass the repository path and any base branch the user supplied; return its report without reading the full diff again. If you are already that subagent, perform the investigation here and do not delegate it again. If the harness has no subagent facility, investigate inline and disclose that limitation.

In a subagent, only the final report goes back to the caller. Read greedily and report tightly. Where a step below needs a decision, make it and say in the report which way you went; don't depend on another round trip to the user.

## Anchor

`BASE` is the base branch the user supplied with the skill invocation or in the request. If none was supplied, use `git symbolic-ref --quiet --short refs/remotes/origin/HEAD | sed 's@^origin/@@'`.

```sh
FORK=$(git merge-base --fork-point "origin/$BASE" HEAD)
[ -n "$FORK" ] || FORK=$(git merge-base "origin/$BASE" HEAD)
```

`--fork-point` is reflog-based: it still finds the real divergence after the base was rebased or force-pushed, but prints nothing on a fresh clone, on a branch made elsewhere, or once the reflog expires — hence the fallback. When the fallback runs, say so in the report; the anchor may sit further back than the true fork point and inflate the diff.

- No `origin/HEAD` → `git remote set-head origin --auto`, or use local `main`/`master` and note it.
- Never `git fetch`. If `origin/*` looks stale, just say so.
- `$FORK` == `HEAD` with a clean working tree → nothing to summarize; stop.
- Current branch *is* the base → there's no branch work to anchor on, and you can't ask which base to use instead. Don't come back empty: summarize any uncommitted changes, list the last 10 commit subjects without reading their diffs, and close by naming what the caller can hand back — a different base, or a commit count.

## Scope

```sh
git log --oneline --no-merges "$FORK"..HEAD
git diff --name-status "$FORK" HEAD
```

Uncommitted work counts. If `git status --porcelain` isn't empty, also read `git diff "$FORK"` (no `HEAD`), and keep committed vs uncommitted separate in the report.

## Exclude generated files

Start with what the repo declares:

```sh
git diff --name-only -z "$FORK" HEAD |
  git check-attr --stdin -z linguist-generated diff |
  tr '\0' '\n' | paste - - -
```

Generated when `linguist-generated` is `set`/`true`, or `diff` is `unset`. `unspecified` → judge by path: lockfiles, `dist/` `build/` `out/` `.next/` `.turbo/` `coverage/`, `*.min.js`, `*.map`, `*.gen.*`, `*_pb.*`, `__generated__/`, build-emitted `*.d.ts`, `__snapshots__/`, visual regression images.

Ambiguous path → read the first few lines for a `@generated` / `DO NOT EDIT` / `Code generated by` marker. Still ambiguous → read the file, don't exclude it. Missing hand-written code is the worse failure.

Then exclude by pathspec, e.g. `git diff "$FORK" HEAD -- . ':(exclude)bun.lock' ':(exclude)**/__generated__/**'`. On a large diff, take `--stat` first to order the reading, not to limit it. Read every hand-written file it lists, largest change first; if the diff is big enough that you can't, say which files went unread.

## Read and report

Commit messages hint at intent; the diff is the evidence. Where the two disagree, report the disagreement. Group changes by theme, not by file.

- One-line summary of what the branch is doing
- Themed groups, each with its paths as `path/to/file.ts:12`
- Anchor: base branch, fork point short hash, commit count, whether the fallback ran
- Excluded generated paths, marked gitattributes vs. guess
- Uncommitted changes, separately
- Anything unclear or unfinished — omit if none
